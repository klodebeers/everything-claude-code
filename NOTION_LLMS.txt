## Relations Graph

Full map of which databases connect to which. Read left → right as "has a relation pointing to."
Dual (↔) means both sides of the relation are explicitly configured.

```
Payment Schedules → Accounts (Account, limit 1)
Payment Schedules → Domains (Domain, multi)
Payment Schedules → Services (Service Defaults, multi)
Payment Schedules ↔ Payments (Payments / Schedule, dual)

Payments → Accounts (Account, limit 1)
Payments → Domains (Domain, limit 1 — one-way)
Payments → Domains (Domain for Rollups, multi — two-way via Domains.Payments)
Payments → Profiles (Entity, multi)
Payments → Tasks (Task, limit 1)
Payments ↔ Payment Schedules (Schedule / Payments — see above)

Accounts ↔ Services (Service / Accounts, dual, limit 1 on Accounts side)
Accounts ↔ Payments (Payments / Account)
Accounts ↔ Payment Schedules (Payment Schedules / Account, limit 1 on Accounts side)
Accounts → Domains (Domains Infrastructure)
Accounts → Domains (Domains Registrar)
Accounts → Email Accounts (Email Account, limit 1)
Accounts → Profiles (Registered Name, limit 1)
Accounts → Departments (End-User, limit 1)
Accounts → API Balances (API Balances, multi)
Accounts → Business Reference (Business Name, limit 1)

Domains → Accounts (Registrar Account, limit 1)
Domains → Accounts (Infrastructure Provider, limit 1)
Domains ↔ Payments (Payments / Domain)
Domains ↔ Payment Schedules (Payment Schedules / Domain)
Domains → Departments (Requester, limit 1)

Services → Accounts (Accounts — back-relation)
Services → Departments (End-User for Rollup, limit 1)
```

# PART 4 — FORMULAS

All formula properties across all databases. Formulas are read-only — cannot be set via API.
To update a formula expression, use `notion-update-data-source` with DDL:
`ALTER COLUMN "Name" SET FORMULA('expression')`

**⚠️ IMPORTANT:** `formulaCode://` URLs cannot be fetched via the `notion-fetch` tool.
To read the raw formula expression, open the database in Notion UI or check the Schema Viewing Layout page.

**formulaResult:// in query output** = formula resultType mismatch — the formula is returning a value
that doesn't match the stored resultType. Queries will show a URL instead of the actual value.
Fix: ALTER COLUMN to correct resultType.

**Formula code references (internal, not fetchable):**
- Cutoff Estimate: `formulaCode://33e07e36-6ebf-81f4-95a3-000bc103952a/bEpPXw`
- At-Risk Start: `formulaCode://33e07e36-6ebf-81f4-95a3-000bc103952a/bHFRQQ`

**Risk window logic:**
```
At-Risk Start  =  Next Payment Due  −  Service At-Risk Lead Days   (earliest point to act)
Cutoff Estimate = Next Payment Due  +  Service Grace Days          (last point before impact)
```

# PART 6 — KNOWN ISSUES

All issues confirmed from live schema reads and Schema Viewing Layout pages.
Require an SCR (Schema Change Request) to fix.

## Formula Result Type Mismatches

| # | Database | Property | Stored resultType | Should be | Fix |
|---|----------|----------|-------------------|-----------|-----|
| 1 | Payment Schedules | Cutoff Estimate | text | date | ALTER COLUMN with correct dateAdd expression |
| 2 | Payment Schedules | At-Risk Start | text | date | ALTER COLUMN with correct dateSubtract expression |
| 3 | Payments | Total Amount | text | number | ALTER COLUMN with correct addition expression |

**Effect:** When resultType is wrong, query results return a `formulaResult://...` URL string
instead of the actual computed value. The formula still computes — it just cannot be read
programmatically until resultType is corrected.

## Duplicate/Ambiguous Relations

|---|----------|-------|----------------|
| 4 | Payments | Two Domain relations: "Domain" (limit 1, one-way) and "Domain (for Rollups)" (multi, two-way) | Decide if both needed. If not, backfill "Domain" from "Domain (for Rollups)" and drop the duplicate. |

# PART 7 — MCP TOOL PATTERNS

How to work with the NCC Notion workspace using the available Notion MCP tools.

## Tool Reference

| Tool | Use for |
|------|---------|
| `notion-fetch` | Read a page, database, or data source by URL or ID |
| `notion-query-database-view` | Query records from a database view |

## Fetch Patterns

```json
// Fetch a page
{ "id": "https://www.notion.so/33e07e366ebf816f8f39d1f8208edf82" }

// Fetch a data source (full schema)
{ "id": "collection://33e07e36-6ebf-81f4-95a3-000bc103952a" }

// Fetch a specific record
{ "id": "https://www.notion.so/33e07e366ebf81b885c6f3f7a47ea978" }
```

## Query Patterns

View URL format: `https://www.notion.so/{db-no-dashes}?v={view-no-dashes}`

```json
// Query Payment Schedules default view
{ "view_url": "https://www.notion.so/33e07e366ebf816f8f39d1f8208edf82?v=33e07e366ebf81b990ed000cd1f708cd" }

// Query Recovery Audit view
{ "view_url": "https://www.notion.so/33e07e366ebf816f8f39d1f8208edf82?v=33e07e366ebf81159 2ef000c0784739c" }

// Query Payments default view
{ "view_url": "https://www.notion.so/33e07e366ebf81f2844cc8bb5ca42db9?v=33e07e366ebf811e86e2000ceb0d217e" }
```

## Update Page Properties

Date properties use the expanded format — three separate keys per date field:
```json
{
  "pageId": "https://www.notion.so/RECORD_URL",
  "properties": {
    "date:Next Payment Due:start": "2026-07-15",
    "date:Next Payment Due:end": null,
    "date:Next Payment Due:is_datetime": 0,
    "Schedule Status": "Active",
    "Expected Amount": 149.99,
    "Notes": "Updated by automation"
  }
}
```

Relation properties:
- Single-limit relation: JSON string `"[\"https://www.notion.so/PAGE_URL\"]"`
- Multi relation: JSON array `"[\"https://www.notion.so/URL1\",\"https://www.notion.so/URL2\"]"`

Checkbox properties:
- `"__YES__"` = true
- `"__NO__"` = false

## Schema Update (DDL)

```json
{
  "data_source_id": "collection://33e07e36-6ebf-81f4-95a3-000bc103952a",
  "statements": "ALTER COLUMN \"Cutoff Estimate\" SET FORMULA('dateAdd(prop(\"Next Payment Due\"), toNumber(prop(\"Service Grace Days\")), \"days\")')"
}
```

## Constraints and Gotchas

| Constraint | Detail |
|-----------|--------|
| formulaCode:// | Not fetchable — returns validation_error. Check Schema Viewing Layout or Notion UI for expression. |
| formulaResult:// in queries | Formula resultType mismatch. The formula works but the value can't be read programmatically until resultType is fixed. |
| Buttons | Cannot be triggered via API. Must use Notion UI. |
| auto_increment_id, formula, rollup | Always read-only. Never write to these properties. |
| Relations (pre-query) | Relation columns return page URLs. To get the linked record's data, fetch each URL separately or query the related database. |
| Before any DDL | Read the Schema Viewing Layout page for the target database first. |
| Every schema change | Requires an SCR (Schema Change Request) — no undocumented changes. |
| formulaCode vs formulaResult | formulaCode:// = the formula's source code reference (not fetchable). formulaResult:// = the formula's output for a specific record (what you see in query results when resultType is wrong). |
